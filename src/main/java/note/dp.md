# DP解法（动态规划）
DP解法是**动态规划（Dynamic Programming）** 解法，是算法中解决「多阶段决策最优解」问题的核心思想，也是面试/笔试的高频考点。
> **DP解法的核心是「用已解决的子问题答案，推导出原问题的答案」** ——把复杂问题拆成多个可重复解决的小问题，通过存储小问题的答案（避免重复计算），最终得到原问题的解。

## 一、为什么需要DP解法？（对比暴力解）
举个最经典的例子——「斐波那契数列」（求第n项的值）：
- 暴力递归（重复计算）：
  ```java
  int fib(int n) {
      if (n <= 1) return n;
      return fib(n-1) + fib(n-2); // 计算fib(5)时，会重复计算fib(3)、fib(2)等
  }
  ```
  问题：时间复杂度 $O(2^n)$，大量子问题重复计算（比如fib(5)需要fib(4)+fib(3)，fib(4)又需要fib(3)+fib(2)，fib(3)被计算了两次）。

- DP解法（存储子问题答案）：
  ```java
  int fib(int n) {
      if (n <= 1) return n;
      // dp数组：存储子问题的答案（dp[i] = 第i项斐波那契数）
      int[] dp = new int[n+1];
      dp[0] = 0;
      dp[1] = 1;
      // 从子问题推导原问题：依次计算dp[2]→dp[3]→...→dp[n]
      for (int i = 2; i <= n; i++) {
          dp[i] = dp[i-1] + dp[i-2]; // 用已解决的子问题答案，算当前问题
      }
      return dp[n];
  }
  ```
  优化：时间复杂度 $O(n)$，每个子问题只计算一次，通过「存储结果」避免重复计算——这就是DP解法的核心价值。

## 二、DP解法的核心特征（3个关键点）
### 1. 最优子结构
原问题的最优解，能由「子问题的最优解」推导而来。
- 比如：求「凑成金额11的最少硬币数」，可以由「凑成10的最少硬币数+1」「凑成9的最少硬币数+1」等子问题的最优解推导；
- 比如：求「最长递增子序列长度」，可以由「以第i个元素结尾的最长递增子序列长度」推导。

### 2. 重叠子问题
解决原问题时，会反复遇到相同的子问题（如果不存储答案，会重复计算）。
- 比如斐波那契数列中，fib(5)需要fib(4)和fib(3)，fib(4)又需要fib(3)和fib(2)——fib(3)就是「重叠子问题」；
- DP解法通过「备忘录（数组/哈希表）」存储子问题答案，让每个子问题只算一次。

### 3. 状态转移方程（DP的灵魂）
描述「如何由子问题推导原问题」的数学公式，是DP解法的核心。
- 斐波那契数列的状态转移方程：$dp[i] = dp[i-1] + dp[i-2]$；
- 凑硬币问题的状态转移方程：$dp[amount] = min(dp[amount - coin] + 1)$（coin为可选硬币面额）；
- 状态转移方程的本质：**子问题答案的组合规则**。

## 三、DP解法的通用解题步骤
以「凑零钱问题」（给定硬币面额，求凑成目标金额的最少硬币数）为例，拆解DP解法的4个步骤：

### 步骤1：定义DP状态（核心）
明确「dp数组/变量代表什么」——这是DP解法的第一步，也是最关键的一步。
- 比如凑零钱问题：定义 `dp[i]` 为「凑成金额i所需的最少硬币数」。

### 步骤2：确定初始条件（边界）
初始化「最小的子问题答案」（无法再拆分的子问题）。
- 凑零钱问题：`dp[0] = 0`（凑成金额0需要0个硬币）；其他 `dp[i]` 初始化为一个大数（比如`amount+1`，表示初始不可达）。

### 步骤3：推导状态转移方程
找到「原问题→子问题」的推导规则。
- 凑零钱问题：对于每个金额`i`，遍历所有硬币面额`coin`，若`i >= coin`，则 `dp[i] = min(dp[i], dp[i - coin] + 1)`。

### 步骤4：计算最终结果
从初始条件出发，按状态转移方程依次计算子问题，直到得到原问题答案。
- 凑零钱问题：从`dp[1]`计算到`dp[amount]`，最终返回`dp[amount]`（若仍为大数，说明无法凑成）。

### 完整代码示例（凑零钱DP解法）
```java
public int coinChange(int[] coins, int amount) {
    // 步骤1：定义DP状态
    int[] dp = new int[amount + 1];
    // 步骤2：初始条件（边界）
    int max = amount + 1;
    Arrays.fill(dp, max);
    dp[0] = 0;
    // 步骤4：计算子问题→原问题
    for (int i = 1; i <= amount; i++) {
        // 步骤3：状态转移方程
        for (int coin : coins) {
            if (coin <= i) {
                dp[i] = Math.min(dp[i], dp[i - coin] + 1);
            }
        }
    }
    // 最终结果
    return dp[amount] > amount ? -1 : dp[amount];
}
```

## 四、DP解法 vs 暴力递归 vs 记忆化递归（对比理解）
为了更清晰，用表格对比三种解法的核心差异：

| 解法         | 核心逻辑                     | 时间复杂度 | 空间复杂度 | 核心优势               |
|--------------|------------------------------|------------|------------|------------------------|
| 暴力递归     | 直接拆分问题，重复计算子问题 | 高（如$2^n$） | 低（递归栈） | 代码简单，易理解       |
| 记忆化递归   | 递归+存储子问题答案（自顶向下） | 低（如$O(n)$） | 中（栈+备忘录） | 兼顾递归直观+无重复计算 |
| DP解法       | 迭代+存储子问题答案（自底向上） | 低（如$O(n)$） | 中（DP数组） | 效率最高，无递归栈溢出 |

- 记忆化递归：是「递归版DP」（自顶向下，比如先算fib(n)，再递归算fib(n-1)和fib(n-2)，并存储结果）；
- DP解法：是「迭代版DP」（自底向上，比如先算fib(2)，再算fib(3)，直到fib(n)）——通常我们说的「DP解法」指这种。

## 五、DP解法的适用场景（判断是否能用DP）
遇到以下特征的问题，优先考虑DP解法：
1. 问题求「最优解」（最少、最多、最长、最短等）；
2. 问题能拆分成「重叠子问题」；
3. 子问题的解能推导出原问题的解（最优子结构）；
4. 无后效性（子问题的解一旦确定，不受后续决策影响）。

### 经典DP问题
- 基础：斐波那契数列、爬楼梯、凑零钱；
- 中等：最长递增子序列、最长公共子序列、不同路径；
- 困难：编辑距离、买卖股票的最佳时机、打家劫舍系列。

## 总结
1. DP解法的本质：**拆分子问题 + 存储子问题答案 + 推导原问题**，核心是「避免重复计算」；
2. 三个核心特征：最优子结构、重叠子问题、状态转移方程（灵魂）；
3. 通用步骤：定义DP状态 → 初始条件 → 状态转移方程 → 计算结果；
4. 关键区别：DP解法是「自底向上」的迭代实现，比递归更高效，无栈溢出风险。

简单记：**DP解法就是「用空间换时间」，把重复算的子问题答案存起来，下次直接用**——这也是它和暴力解最核心的区别。
